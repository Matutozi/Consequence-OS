No receipt, no action.

ConsequenceOS sits between an AI agent and the tools it calls. It checks every call against your policy, holds risky ones for a person, and gives every call it lets through a signed receipt that the service on the other end can check.

Why receipts

Approval gateways already hold calls for a person, but the service that finally acts never sees that approval. It has to trust whatever reached it. A ConsequenceOS receipt is proof it can check: which rule, or which named person, allowed exactly this call, with these arguments, once, in the last five minutes.

Receipts are signed twice, with Ed25519 and the post-quantum ML-DSA-87, and both signatures must hold. Every decision goes into a hash-chained audit log the agent can't touch, which shows any edit, and which can be anchored on a public chain.

Three ways in

No integration

A hook on your coding agent

Every file edit and shell command Claude Code makes goes through the policy. Secrets stay out of reach, and the agent can't switch the guard off. No server, no database.

Config only

A proxy in front of any MCP server

ConsequenceOS holds the upstream token, so the agent can't go around it. The system behind it doesn't change.

Full

Receivers that check receipts

Middleware in Go or Python refuses any call without a valid receipt for that exact call. The strongest guarantee, and always optional.

Try it on Claude Code

As a Claude Code plugin, from the repository's own marketplace:

/plugin install consequenceos --marketplace Matutozi/Consequence-OS

Or install consequenced yourself and set up the hook in a project:

go install github.com/matutozi/consequence-os/cmd/consequenced@latest
cd ~/code/my-project
consequenced -init claude-code

Linux and macOS. The starter policy lets reads and in-project edits through, asks before other shell commands, and blocks secrets and changes to the guard itself. See ConsequenceOS on your own machine.

Anchored on Concordium

A guarded agent can be registered in Concordium's Agent Registry, with an Agent Card that names its guard and its public keys. The audit log's head is anchored in the agent's record, where only its owner can write and anyone can read. If someone later cuts entries out of the log, the anchor no longer matches, and anyone can see it.

The cards of agents registered from this project are hosted under /agents/. See Anchoring on Concordium.

What it doesn't do

  • It doesn't detect prompt injection or judge whether an instruction is good. It limits what any agent can do, however it was misled.
  • It covers calls made through MCP and through Claude Code's tools. An agent that calls APIs directly, around it, isn't covered.
  • The Claude Code hook is enforced by Claude Code, not the operating system. It isn't a sandbox.
